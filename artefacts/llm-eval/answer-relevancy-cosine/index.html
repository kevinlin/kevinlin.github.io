Cosine similarity inside Ragas answer relevancy

Ragas asks an LLM to reverse-engineer N questions from the generated answer, embeds them, and measures how far each one points away from the original user input in embedding space. Drag any question vector below to see the score move.

answer relevancy = (1 / N) · Σi=1..N cos(Egi, Eo) = (1 / N) · Σi=1..N ( Egi · Eo ) / ( ‖Egi‖ ‖Eo‖ )
Eo
embedding of the original user input
Egi
embedding of the i-th question generated back from the answer
N
number of generated questions (the strictness parameter, default 3)
·
dot product — sums the coordinate-wise products, large when the vectors lean the same way
‖v‖
vector length; dividing by both lengths strips magnitude out, leaving only direction

What the geometry tells you

  • 0° means the answer let the LLM rebuild your exact question. cos 0 = 1. The answer covered everything asked, nothing more.
  • A wide angle means drift. An answer covering only half the question ("France is in western Europe" for "Where is France and what is its capital?") generates questions that miss the capital, so their vectors tilt away and the mean cosine drops.
  • Length is deliberately ignored. Embedding norm tracks things like text length and token count, not meaning. Dividing by ‖Egi‖‖Eo‖ makes a verbose paraphrase score the same as a terse one — that is the whole reason cosine is used here instead of a raw dot product or Euclidean distance.
  • The range is [-1, 1], not [0, 1]. Ragas notes the score is usually in [0, 1] but is not bounded there — real embedding models rarely produce opposing vectors, yet nothing in the formula forbids a negative cosine.
  • Relevancy is not correctness. The metric only compares question to question. A confidently wrong but on-topic answer still scores high. Non-committal answers ("I don't know") get flagged separately by a noncommittal check, not by the cosine.
