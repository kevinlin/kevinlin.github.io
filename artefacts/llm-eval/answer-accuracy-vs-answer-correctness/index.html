Answer accuracy vs answer correctness

Two Ragas metrics that both compare a generated response against a reference — and nothing else. Neither touches retrieved context. They differ in how they reach a number: Answer Accuracy asks an LLM twice and averages a coarse rating; Answer Correctness blends embedding similarity with claim-level F1. Reading the difference

  • Wording leaks into Answer Correctness. Half the score is cosine similarity between embeddings, which moves with phrasing, length and register. A terse but fully correct answer scores lower than a verbose one that says the same thing. Answer Accuracy has no such term.
  • Answer Correctness can be propped up by fluency. A confidently wrong answer that reads like the reference keeps a high semantic component, so a single bad claim only dents the score. Drop the semantic weight to 0 and the metric collapses to factual F1 — that is the honest setting when you care about facts alone.
  • Answer Accuracy is coarse by construction. Three rungs per pass, two passes: only five possible scores (0, 0.25, 0.5, 0.75, 1). Useful as a gate, poor as a trend line — small regressions hide inside a rung.
  • The swapped pass is the point. LLM judges favour whichever text is presented first or looks more authoritative. Rating the reference against the response, then averaging, cancels much of that. Answer Correctness has no equivalent symmetry.
  • Explainability runs the other way. When a score drops, Answer Correctness names the claim that broke. Answer Accuracy gives a number and no reasoning, so debugging means rerunning by hand.
  • Practical split: Answer Accuracy for cheap, robust CI gates on small models; Answer Correctness when someone has to explain why a score moved.
